# M1 Agent 协作协议

> 核心理念：**用「契约 + 验收标准」约束结果，不用「操作步骤」约束过程。**
> 次要但同样重要：**规则要少。** 规则塞太多，agent 光对清单就耗掉半条命，跑一会就报阻塞——效率是第一位的。
> 所以下面只有 **3 条铁律 + 4 条红线 + 5 项自检**，其余全是不作为打回依据的「约定」。

---

## 1. 角色分工

| 角色 | 是谁 | 干什么 | 不干什么 |
|---|---|---|---|
| 产品 & 终审 | 你 | 定方向、拍板、跑 Codex、试玩手感 | 不写代码 |
| 施工 | Codex（交互模式，gpt-5.6-sol，unity-mcp 已通） | 实现工单：写代码、调 Unity、跑测试、自检 | 不定范围、不改验收标准 |
| 主管 & 验收 | Claude（unity-mcp 已通） | 拆单、逐单验收、出审核报告、维护计划文档 | 不抢着写实现代码 |

**为什么写和审要分开**：同一个模型自审等于没审。不同模型交叉才能真发现问题。

## 2. 三条铁律

### 铁律一 · 默认自己决定，该问就问

**默认**：局部的、可逆的、成本小的选择一律自己定，追加到 `DECISIONS.md`。
命名、目录结构、类拆分粒度、用不用某个 Unity API、加不加字段、JSON 怎么排——全部自己定，不要问。

**以下四类必须停下来问**：
1. 与已确认的文档 / 已定契约冲突
2. 需要推翻已验收通过的模块
3. 影响面跨工单或不可逆：数据契约变更、技术选型、引入新依赖、目录大改
4. 两个方案成本差一个量级，且自己没把握选哪个

**提问的两个附加条件**（这两条是防止「问」变成「停」的关键）：
- 必须**带 A/B 方案和推荐项**，不要开放式甩问题
- **等待期间继续做不依赖该决定的部分** —— 问 ≠ 停摆

### 铁律二 · 三次法则

同一个报错 / 同一个卡点尝试 **3 次**仍不通 → **立刻换方案继续走**，哪怕换成更笨的方案。
把原方案与失败原因写进 `TECH_DEBT.md`。禁止在同一个坑里反复刨。

### 铁律三 · 先跑通再优雅

**任何时刻，仓库必须处于「能进 Play 且控制台无 Error」的状态。**
宁可留 `// TODO(WO-B3): 自爆 AOE 待接` 的空实现，也不许提交编译不过的半成品。

## 5. 我的验收清单

| # | 手段 | 查什么 |
|---|---|---|
| 1 | `read_console` | Error / Warning，尤其被吞掉的异常 |
| 2 | `run_tests` + 覆盖率报告 | 全绿；用例是否真覆盖验收标准，不是凑数空断言 |
| 3 | `git diff` | 只看结构：契约有没有被偷改、规则有没有漏进 View 层、胜负判定是不是单一出口、数值有没有硬编码 |
| 4 | JSON diff | 数值是否落在合理量级 |
| 5 | `manage_editor play` + `HanziDefend/Screenshot` | 读截图核对布局、阵营辨识度、UI 安全区 |
| 6 | ~~美术单~~ | 美术不再由 agent 产出或验收，见 `Docs/Art/README.md` |
| 7 | DECISIONS / TECH_DEBT | 有没有把重要决定藏起来不写 |

**审核报告格式**（`Docs/Plan/REVIEW/WO-xx.md`）
```
结论：通过 / 有条件通过 / 打回
证据：控制台 X 条 Error、测试 Y/Y 绿、覆盖率 Z%、截图 <路径>
必改项：（可直接粘回 Codex 的、具体到文件与行为的修复清单）
建议项：（不阻塞验收）
本轮新增技术债：
```

**我不会打回的事**：命名风格、类拆得多还是少、注释多少、用不用 LINQ、文件放哪个子目录、实现思路跟我想的不一样。

## 7. `AGENTS.md` 草案（确认后落到仓库根目录，Codex 自动读）

```markdown
# HanziDefend · Agent 常驻规则

汉字·兵器三国。Unity 6000.3.11f1 + URP 2D，竖屏 1080×1920，终点是微信小游戏。
当前里程碑：M1 战斗 Demo。范围见 Docs/Plan/M1-00-总体方案.md。

## 四条红线（违反即工单不通过）
1. 玩法规则不许写进 View 层；View 不做任何数值或胜负判断。
2. 胜负判定只有一个出口 `TrySettle()`，判定后立即冻结 tick。
3. 数值只写在 `Assets/GameData/*.json`，代码里不硬编码数值。
4. 随机一律走 `Data.Rng`（带 seed），禁止 `UnityEngine.Random`。

## 两条架构要求
- `BattleSystem.Tick(float dt)` 必须能被测试代码连续调用 N 次，玩法逻辑不埋在 Update() 里。
  物理用 `Physics2D.simulationMode = SimulationMode2D.Script` + `Physics2D.Simulate(dt)` 手动步进。
- `Assets/Scripts/Data/` 保持纯 C#（它只有数据结构和公式）。
  `Gameplay/` 层可以自由使用 Physics2D、Transform、协程、对象池等一切引擎能力。

## 工作方式
- 工单没写到的局部选择，自己决定并记 `Docs/Plan/DECISIONS.md`，不要停下来问。
- 只有这四类才停下来问，且提问要带 A/B 方案和推荐项：
  与已确认文档冲突 / 要推翻已验收模块 / 跨工单或不可逆的变更 / 两案成本差一个量级且没把握。
  提问期间继续做不依赖该决定的部分——问 ≠ 停。
- 同一个坑试 3 次不通就换方案（哪怕更笨），失败原因记 `Docs/Plan/TECH_DEBT.md`。
- 任何时刻仓库必须能进 Play 且控制台无 Error。宁可 TODO stub，不可编译不过。
- 收工前跑 `Docs/Plan/M1-03-Agent协作协议.md` §4 的 5 项自检。

## 约定（不作为打回依据，但照着做省事）
- 场景与 Prefab 由代码 / Editor 命令生成，不手工编辑 .unity / .prefab 的 YAML。
- 美术引用走约定路径 + `art_manifest.json`，不在 Inspector 里手拖引用。
- 技能与 BUFF 做成「效果指令」数据（见 M1-00 §2.7），由 C# 解释器执行。

## 面向微信小游戏的长期约束（现在免费，以后很贵）
- 不用反射、不用动态代码生成、不在运行期依赖 Editor-only API
- 不开实时光 / 阴影 / 后处理 / HDR
- 单张贴图 ≤ 1024，走 SpriteAtlas
- 资源加载走抽象接口，不散落 `Resources.Load`

## 常用 MCP 动作
- 改完代码：`read_console` 看编译结果；轮询 `editor_state.isCompiling` 等域重载结束再调用新类型
- 验收：`run_tests`（EditMode / PlayMode）
- 看画面：`manage_editor play` + 菜单 `HanziDefend/Screenshot` → `Assets/Screenshots/`
```

## 8. 常见卡点的预置解法

| 卡点 | 直接这么做 |
|---|---|
| 域重载后类型找不到 | 轮询 `editor_state.isCompiling` 到 false 再继续 |
| 场景改动难 review / 冲突 | 改成 Bootstrap 代码装配，场景文件保持几乎不变 |
| Prefab 引用丢失 | 改成 Editor 菜单命令重新生成，不手工修 |
| 需要在 Inspector 拖引用 | 改成约定路径 + 生成清单 |
| Unity 某 API 在 6000.3 行为异常 | 试 3 次即换 API，记 TECH_DEBT |
| 测试需要真实帧率才能跑 | 说明 Tick 没做成可手动驱动，改结构而不是改测试 |
| 美术资源还没到 | 用占位块（WO-A1 生成器），绝不因此停工 |
| 数值不知道填多少 | 拍一个合理值填上，WO-E1 统一调 |
