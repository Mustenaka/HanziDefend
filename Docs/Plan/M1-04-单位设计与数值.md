# M1 单位设计与数值

> 本文是**单位阵容、克制系统、数值总表、占格与卡池解锁**的唯一权威来源。美术见 `Docs/Art/README.md`。
> 数值经 `balance_v5` 验算：克制网 9 条关系全部达标，14 个单位中 12 个价值密度落在 0.88~1.24。

---

## 1. 设计目标：帝国时代 4 式克制网

不是单纯的护甲加减，而是两条互锁的剪刀石头布：

```
主环：长矛 ──克──▶ 骑兵 ──克──▶ 弓兵 ──克──▶ 长矛
副环：弩兵/弩车 ──克──▶ 重甲 ──抗──▶ 弓箭 ──克──▶ 弩兵
攻城：弩车/冲车 ──克──▶ 建筑（BOSS / 基地）
```

关键设计决定：**克制由「攻击类型 × 护甲类型」+「对位加算伤害」两层表达**，
其中第二层是**加算**而不是乘算（AoE4 的做法）。乘算会让倍率指数爆炸，加算好调且不会失控。

`弩` 归入**器械**类型（机械弓），因此「弩克重甲」是类型自带的 4.0 倍，
不需要打补丁。这是第一版设计里「弩兵对重甲没体现出来」的根因。

## 2. 三个新枚举

**兵种类型 `unitType`**：`步兵 | 骑兵 | 水兵 | 空军 | 建筑 | 特殊`
（M1 只用 步兵/骑兵/建筑/特殊；水兵、空军留字段不实现。我方基地与 BOSS 均为 `建筑`）

**护甲类型 `armorType`**：`无甲 | 轻甲 | 重甲 | 建筑`

**攻击类型 `atkType`**：`斩击 | 打击 | 弓箭 | 器械`

### 2.1 克制矩阵（乘算层）

| 护甲＼攻击 | 斩击 | 打击 | 弓箭 | 器械 | 受击期望 |
|---|---|---|---|---|---|
| 无甲 | **2.0** | 0.5 | **2.0** | 0.5 | 1.625 |
| 轻甲 | 1.5 | 1.0 | 1.0 | 1.0 | 1.225 |
| 重甲 | 0.5 | **2.0** | 0.5 | **4.0** | 1.075 |
| 建筑 | 0.5 | 1.0 | 0.25 | **2.0** | 0.650 |
| *输出期望* | 1.45 | 0.95 | 1.25 | 1.35 | |

每一列都有强项和弱项，没有万金油也没有废类型：
- **斩击** 屠轻装，被重甲和建筑弹开
- **打击** 破重甲，但打无甲只有半伤（钝器打不着灵活轻兵）
- **弓箭** 屠无甲，对重甲/建筑几乎无效
- **器械** 破重甲与建筑，但打不着灵活小兵

受击期望形成干净阶梯：无甲 1.625 → 轻甲 1.225 → 重甲 1.075 → 建筑 0.650。

> 期望值按战场构成 无甲 40% / 轻甲 35% / 重甲 15% / 建筑 10%，
> 敌方攻击构成 斩击 45% / 打击 15% / 弓箭 30% / 器械 10% 计算。
> **波次编排必须贴近这个分布**，否则某几个兵种会没有用武之地（见 §6）。

### 2.2 对位加算伤害（加算层）

`UnitDef` 新增 `bonusVs: [{ target, value }]`，`target` 可以是兵种类型或护甲类型。

| 单位 | 对位加成 | 作用 |
|---|---|---|
| 长矛 | 骑兵 **+60** | 反骑核心。加算而非乘算，所以对轻骑 3.32x、对重骑 2.32x，重骑更难啃但仍能啃 |
| 弩兵 | 重甲 **+40** | 在类型自带 4.0 之上再加固 |
| 弩车 | 建筑 **+400** | 攻城王，把「反建筑」从器械类型里拆出来给专职单位 |
| 冲车 | 建筑 **+900** | 破城锤 |

### 2.3 伤害公式（替换 M1-00 §3.3）

```
armorMitig = max(0, armorVal - pierce) / (max(0, armorVal - pierce) + 100)
typeMult   = 矩阵[被击方护甲类型][攻击方攻击类型]
bonus      = Σ 命中的 bonusVs 加值
damage     = max(1, round( (atk × typeMult + bonus) × (1 - armorMitig) ))
```

数值护甲（`armorVal` / `pierce`）保留，负责平滑线性减伤；
护甲类型负责离散克制。两套并存，与 AoE4 / War3 同构。

### 3.3.1 城堡血量的推导框架：生命期伤害模型（WO-E4）

> 这是目前**唯一有实测支撑**的调参框架。原先「有器械 12.5 秒 / 无器械 50.7 秒」那套
> 纯 DPS 反推**已作废**——它既没算城堡反击，也没算部署是一次性的（死了不会补）。
> WO-E4 用 200 局批跑证伪了它：`B_fair_s5` 理论 DPS 264.2（比含器械阵容 A 的 172.0 还高 54%），
> 实测**0 胜**。完整报告见 `Docs/Plan/REVIEW/WO-E4.md` 与 `REVIEW/WO-E4-Results/`。

**真正的约束不是 DPS，是「生命期伤害」**——一个单位从出生到被城堡打死，
总共能对城堡打出多少点伤害。因为部署是一次性的，这个量有硬上限，**不随时间线性增长**。

推导链条：

1. **城堡射程 2.2 是分水岭。** 全表只有 `gong` 4.5 / `nub` 5.5 / `nuc` 7.0 三个单位射程超过它，
   可以站在射程外免费输出；**其余全部近战单位必须走进 2.2 以内挨打**。
2. **进了射程就变成对拼。** 以 `lia`（链甲兵）为例，它对城堡 97.2 DPS，城堡对它 98.1 DPS，
   几乎 1:1 —— 一个 `lia` 在被打死之前只能带走 **1585 点**。
3. **装箱上限封顶。** 把最优阵容装满可用格子，非器械路线的生命期伤害总和：

   | 可用列数 | 生命期伤害上限 | 对 6000 HP 城堡 |
   |---:|---:|---|
   | 3 列 | 814 | ❌ |
   | 5 列 | 3771 | ❌ |
   | 7 列 | 5569 | ❌ 仍然打不穿 |

   实测达成率 61~69%（`B_fair_s5` 理论 3771，实打 2313~2586），模型是准的。

**两条可执行结论：**

- **改城堡 ATK 的杠杆远大于改护甲。**
  ATK 出现在生命期伤害的**分母**里（我方单位活多久由城堡 DPS 决定），
  护甲只抬我方单发伤害、**不延长我方存活**。
  WO-E4 的护甲对照实验证实了这点：护甲 40→25 后单发变化完全符合预期（弓 4→5、盾 17→19），
  但**胜率一格没动**，生命期伤害上限只从 3771 抬到 4324，仍 < 6000。
- **7×7 掩码网格会直接抬高 5569 这个天花板本身**（可部署格数变多 = 可投放的生命期伤害变多），
  所以在网格落地前调城堡数值必被推翻——这正是当前 6000/60 只能算临时值的原因。

**下一步（尚未执行）**：7×7 网格跑起来后，第一个要验证的就是「改城堡 ATK」这条方向。

## 4. 场地、解锁与卡池

> **WO-C5 起，网格契约整体替换。** 旧版「3×3 起、最多 7×3、按列扩建」已废止，
> 连同「卡池按网格列数解锁」的 `minGridCols` 门槛一并移除。下文是现行唯一规则。

### 4.1 场地：固定 7×7，初始解锁正中心 3×3

场地**永不变大**，只有「已解锁格」会变多。

```
行6  · · · · · · ·          ·  锁定（40 格）
行5  · · · · · · ·          ■  初始解锁（9 格）
行4  · · ■ ■ ■ · ·
行3  · · ■ ■ ■ · ·          列0 .. 列6
行2  · · ■ ■ ■ · ·          行0 最靠近我方基地
行1  · · · · · · ·
行0  · · · · · · ·
        ↑ 我方基地在行0 之外（economy.json 的 baseAnchorRowOffset = -1）
```

尺寸与初始解锁区写在 `levels.json`，代码不硬编码：

```json
"gridWidth": 7,
"gridHeight": 7,
"initialUnlock": { "col": 2, "row": 2, "width": 3, "height": 3 }
```

解锁掩码存在 `RunState.UnlockedCells`（49 个 bool，行主序）：
**跨小关继承，大关结束随 `RunState` 一起重置回 `initialUnlock`。**

### 4.2 七种解锁卡

| 形状 | 占格 | 说明 |
|---|---:|---|
| `1×1` | 1 | 补缝 |
| `2×1` | 2 | 横向 |
| `1×2` | 2 | 纵向 |
| `2×2` | 4 | 最大块 |
| `2×2 缺角` | 3 | 缺角方向（左下/右下/左上/右上）抽卡时随机其一 |
| `3×1` | 3 | 横向长条 |
| `1×3` | 3 | 纵向长条 |

七种等权重抽取；抽到缺角款再等权重抽四个方向之一。全部走 `RngStreams.CardDraw`，同 seed 同序列。

### 4.3 放置合法性：三条硬约束

一次解锁放置合法，当且仅当同时满足：

1. **不越界**：覆盖的每一格都在 7×7 内
2. **有增量**：至少新解锁一格（覆盖到已解锁格是允许的，部分重叠不算浪费，但全落在已解锁区上非法）
3. **贴合**：至少有一格与已解锁区正交相邻（共边），或直接覆盖到已解锁格

第 3 条保证掩码**永远是单一连通区域，不会长出孤岛**。
七种形状自身都是边连通的，所以「有一格贴上」等价于「整张卡贴上」。

### 4.4 三条解锁获取途径 + 每小关自动解锁

| 途径 | 代价 | 产出 |
|---|---|---|
| 看广告 | 一次激励视频（`IAdService` / M1 用 `MockAdService`） | 随机 1 张解锁卡进手牌 |
| 抽卡池 | 手牌抽取，权重 `cardWeights.unlock` = 15 | 随机 1 张解锁卡 |
| 金币购买 | `40 + 20 × 本大关已购次数` | 随机 1 张解锁卡进手牌 |

**打出解锁卡本身免费**——付费点在「拿到卡」，不在「用掉卡」。
全场解锁完毕后：购买与广告都返回 false，卡池 `unlock` 权重归 0 并按比例重分配给其余三类。

**自动解锁**：每通过一个小关，自动解锁 `autoUnlockPerMinorStage`（当前 1）格。
选格规则**完全确定、不消耗任何 RNG**，候选限定为「已贴合已解锁区」的锁定格，逐级打破平局：

1. 到基地锚点 `((width-1)/2, baseAnchorRowOffset)` 的欧氏距离最小
2. 行号更小（更靠近基地）
3. 列号距中心更近
4. 列号更小

从初始 3×3 出发，前 8 格依次是：
`(3,1) → (3,0) → (2,0) → (4,0) → (1,0) → (5,0) → (2,1) → (4,1)`。
全部 49 格解锁后不再触发，返回空且不报错。

### 4.5 装箱：初始 3×3 能放几个

初始解锁区就是一个 3×3，所以旧版 3 列装箱结论**原样成立**：

| 组合 | 用格 | 结果 |
|---|---|---|
| 3×`1×1` + 1×`2×2` | 7/9 | ✅ |
| 1×`3×1` + 1×`2×2` | 7/9 | ✅ |
| 1×`2×2` + 1×`1×2` + 1×`2×1` | 8/9 | ✅ |
| 2×`2×2` | 8/9 | ❌ 放不下（解锁任意一侧一列后即可） |

初始 3×3 的可放位置数（**取代旧的「3~7 列 × 五种占格」表**，
因为可放位置数现在是掩码的函数、不是列数的函数）：

| 占格 | 初始 3×3 的可放位置数 |
|---|---:|
| 1×1 | 9 |
| 2×1 | 6 |
| 1×2 | 6 |
| 2×2 | 4 |
| 3×1 | 3 |
| 1×3 | 3 |
| L 形（`nuc` / `chc`，2×2 外接缺一角） | 4 |

### 4.6 卡池解锁改为几何判定

`economy.json` 的 `shapeUnlocks` **不再带 `minGridCols`**，只声明卡池认识哪些占格。
一个兵种卡是否出现在卡池，由一句几何问题决定：

> **当前已解锁区域里，是否存在该形状的合法放置位？**

- 判定用单位的**真实占格**（L 形按 3 格算，不按 2×2 外接矩形），与部署校验同一套 `UnitFootprint`
- **忽略占用**：只问几何放不放得下，不问格子空不空。
  否则网格站满时整个卡池会塌成空集，而「拖到同 id 同级目标上合成」本来就是合法操作
- 放不下 → 该兵种权重归 0，剩余合法兵种按原比例重分配（单位池内均匀，等价于按比例）

**副作用（已知且接受）**：初始 3×3 已经放得下全部 14 个我方单位，
所以**开局不再有任何形状门槛**。渐进解锁的动机从「解锁新形状」变成
「同时摆得下更多单位」——这正是本次改版要的：几何自然产生节奏，不靠人为门槛。

反向仍然成立：如果掩码被压到 1 格宽（例如只剩一条竖条），
`2×1` / `2×2` / `3×1` / L 形全部出局，卡池只剩 `zu` / `gong` / `huo` / `bing` / `mao` / `nub`。
这条由 `DeploymentGridTests` 与 `CardEconomyTests` 各锁一遍。

### 4.7 给 UI 的公开查询接口（表现归 WO-C4）

- `DeploymentGrid.IsUnlocked(GridCoordinate)` —— 某格是否已解锁
- `DeploymentGrid.IsFootprintUnlocked(UnitFootprint)` / `HasUnlockedPlacement(...)` —— 某形状是否有合法位
- `DeploymentGrid.GetUnlockedAnchors(...)` / `GetAvailableAnchors(...)` —— 合法位（后者额外要求格子空闲）
- `DeploymentGrid.GetLegalUnlockAnchors(UnlockCard)` —— 某张解锁卡能贴哪些位置
- `DeploymentGrid.UnlockedCellCount` / `IsFullyUnlocked`

## 6. 波次编排约束

克制系统只有在敌方构成贴近期望分布时才有意义。硬要求：

| 阶段 | 无甲 | 轻甲 | 重甲 | 说明 |
|---|---:|---:|---:|---|
| 第 1~6 波 | 70% | 30% | 0% | 教学期，斩击/弓箭单位就够 |
| 第 7~12 波 | 45% | 40% | 15% | 重甲登场，逼玩家配打击/器械 |
| 第 13~19 波 | 35% | 35% | 30% | 克制压力最大 |
| 第 20 波 | — | — | — | BOSS（建筑） |

**若重甲比例长期低于 15%，链甲兵与弩兵会失去存在意义**（它们打无甲只有 0.5 倍）。
这是 WO-E1 批跑时要一并验证的指标。
