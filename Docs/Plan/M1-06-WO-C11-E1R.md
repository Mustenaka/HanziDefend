# WO-C11 · 大卡不再重复印名字（小项，先做）

## 背景

WO-C10 把美术提为卡面主体之后，暴露一件改之前看不见的事：
**本作的美术本身就是汉字造型的兵器**，卡面再叠一层文字标签 = 同一个词印两遍。

- 「铁甲兵」(2×2)：美术里的三个字 + 白色横排「铁甲兵」，不同字号不同位置
- 「弩车」(L形)：金色「弩」与白字「弩车」笔画互相穿插，**已经读不出来**
- 1×1（卒/弓/火/冰）不受影响：文字铺满整卡，美术本就只剩一条边

## 要求（用户已拍板）

**footprint ≥ 2 格的卡不印名字标签；1×1 保留文字。**

阈值进 `economy.deployUi`，不要写死在代码里。

## 注意

- 名字没了之后，**信息面板（WO-C9）就是识别单位的唯一兜底**，确认它在大卡上仍然可达
- 手牌区的小卡是另一套尺寸，按同一条 footprint 规则判断，不要按像素大小判断
- 别动 WO-C10 的层级顺序与 `unitCardTintAlpha` 校验

## 顺带（美术管线约束，工程侧只需加校验）

「弩车」边框角标是蓝色（2级）但卡面主色是暗红——它的美术素材**自带不透明暗红背景**，
把下层等级色底整个盖住了。等级识别没丢（边框+角标仍读作蓝），但卡面主色变成由素材决定。

**加一条导入期或加载期校验**：单位美术应为透明底。发现不透明底时给出可定位的警告
（哪个 unitId、哪张图），不要静默通过，也不要直接报错阻断——占位图阶段还会有一批不合规的。

## 我看到的结构性问题（是线索，不是指令）

**1. 难度曲线全压在波次上。**
S1 与 S5 的城池血量、起始金币**逐字相同**，但目标胜率要从 55–75% 拉到 30–50%。
一整条曲线只靠一个杠杆撑，这是 `baseHp` 当初被当成临时值写下、后来没有按关卡重新推导的痕迹。
`levels.json` 里 `baseHp` 本来就是**逐关字段**，让它逐关不同不需要改结构。

**2. 4000 这个数可能仍然偏高。**
7 列最优装箱 5569 × 达成率 0.65 ≈ **3620 < 4000**。
若这个估算成立，那么即使玩家解锁到 7 列、还打出最优阵容，**也打不掉城池**——
胜率会被钉死在低位，怎么调波次都上不去。

**但这是我拿 E4 在 S5 上测的达成率去套 7 列的粗算，我没有实测。**
达成率随列数、阵容、波次都会变。**请你先测，别先信。**

**这条有个可证伪的推论，请用它来检验假设：**
胜率 48%、均时 181.5s 超标、5 局 timeout —— 这三个症状**如果同源**，
根因就是「打不掉城池 → 打到超时 → 判负」，那么**只降 `baseHp` 一个量，三个指标应当同时改善**。

反过来：**若胜率上去了但时长没下来，这个假设就是错的**，说明拖长局面的是别的东西
（例如双方僵持在射程外、或某类单位互相打不动），此时不要继续压血量硬凑胜率——
那只会把「打不完」换成「速胜」，中间的手感一样是坏的。请转而去查时长的真实成因。

**3. 解锁节奏是没被算进模型的隐变量。**
装箱上限是列数的函数，而列数由解锁卡决定。玩家在 S1 实际能到几列、S5 能到几列，
决定了各关的真实伤害天花板。这条 E4 没覆盖。

## 做法（你自己定，以下是可选路径）

- 先**实测**各关在正常解锁节奏下的可达列数与实打寿命伤害，把「达成率」按关卡测出来
- 再由此**反推**每关 `baseHp` 应该是多少，让 S1 落在 55–75%、S5 落在 30–50%
- 起始金币、波次组成、解锁节奏都是可动的杠杆，但**优先动派生量（城池血量），
  少动 M1-04 的单位数值**——单位数值是单一事实源，改一处会波及计数门禁与反制矩阵

## 必须满足

1. **≥2 套阵容**（含器械 / 无器械各至少一套）都要报胜率，不许只用最优阵容凑数
2. **负对照**：把调好的数值改回去，确认验收门禁**确实变红**；再逐字节还原
3. 随机性一律走 `Data.Rng` 的既有流，**不要新引入种子**，否则历史对照失效
4. 结论写进 `Docs/Plan/DECISIONS.md`：每关 `baseHp` 是**怎么推出来的**，
   不要只留一个调好的数字——下次改单位数值时要有人能重新推一遍
5. `[Ignore]` 拿掉，验收用例绿

## 边界

- 不改验收目标区间（见红线）
- 不改 `Assets/Scripts/View/` 下的任何东西（那是 C11 的地盘，避免两单互踩）
- 不改反制矩阵 `damage.typeMultipliers`——那是 WO-B2 验过的设计，胜率低不是它的错
