# 图标生产清单（22 张）

> 配套 `README.md` §2 命名规范 / §3 尺寸规范。这是一份**生产用工作表**，出完即可归档。
> 效果 id 与 `Assets/GameData/effects.json` 对应，标「补」的还没落进数据（见 §5）。

---

## 1. 规格

| 项 | 值 |
|---|---|
| 生成画布 | 1024×1024，比例 1:1 |
| 入库尺寸 | 128×128 |
| 背景 | 纯白 `#FFFFFF`，无 alpha |
| 命名 | `icon_{名称全拼}_{group}_{风格全拼}_v{NN}.png`，group ∈ `buff` / `skill` / `res` |
| 硬指标 | **缩到 64px 主字仍可辨认** |

两条容易踩的：

- **不要画外框** —— 外框由 UI 九宫格提供，图标自带框会和卡牌底板打架
- **不分稀有度** —— 稀有度靠卡牌底板颜色表达，一个效果只要一张图

---

## 2. 为什么走「汉字 + 象征件」

抽象概念（死战、坚阵、屯粮）直接让 AI 画，十张有八张跑偏。取效果名里一个字做主体、配一个小象征件，
既稳定又和角色卡的视觉语言完全统一，64px 下靠字就能认。下表 20 个主字全部不重复。

---

## 3. 统一 prompt 模板

```
参考前三张图片的设计风格，设计一个游戏图标，主体是「{字}」字，{象征件}。方形构图，不要外框。同时用白色底，不要有背景。
```

金币和扩建格这两张**不用字**，直接画物件——它们要和数字并排显示，带字会打架。

## 6. 不用单独生成的

**战斗内状态图标**（点燃 / 减速 / 护盾，挂血条旁的 32~48px 小标）
—— 直接复用 `燃`、`冰`、`坚` 三张缩小，不另出图。
（把「攻击附带点燃/减速」设计成 BUFF 的原因之一就是一份美术两处用。）

**单位自带技能**（冲锋 / 践踏 / 穿甲箭 / 火爆）
—— M1 全是自动触发，界面上没有按钮，不需要图标。卡牌详情页是 M2 的事。

## 7. 附：`effects.json` 需要补的 9 条

图标可以先出，但这 9 个效果得落进数据才能被结算抽到。这是 Codex 的活，一个小工单：

```
buff_hp_up        固本      AddStat  AllyAll  hp        mul +0.15   Common
buff_move_up      奔袭      AddStat  AllyAll  moveSpeed mul +0.15   Common
buff_aspd_up      疾矢      AddStat  AllyAll  atkSpeed  mul +0.12   Common
buff_armor_up     重铠      AddStat  AllyAll  armor     add +8      Uncommon
buff_pierce_up    穿甲      AddStat  AllyAll  pierce    add +8      Uncommon
buff_coin_gain    屯粮      击杀金币 +50%                            Uncommon
buff_last_stand   死战      血量 <30% 时 atk mul +0.5                Rare
buff_burn_on_hit  燃烧      攻击附带点燃（持续百分比掉血）             Rare
buff_slow_on_hit  冰封      攻击附带减速                             Rare
skill_meteor      天雷      Damage  EnemyInRadius                    Epic
```

后三条（`屯粮` / `死战` / `燃烧` / `冰封`）现有 op 集表达不了，需要扩 op 或加触发条件——
让 Codex 自己判断是扩 `AddStat` 的条件字段还是加新 op，记 `DECISIONS.md` 即可。
