# M1 美术管线规范（gpt-image2 生产标准）

> 流程一句话：**在 GPT 对话里按模板出图（纯白底）→ 下载丢进 `Docs/Art/_inbox/` → 跑 `art_intake.py` → Unity 自动成 Sprite → 看 contact sheet 验收。**
> 全程零手工 PS、零 Inspector 拖引用。

> **2026-08-12 生成策略更新：**实际生产改为“效果参考图主导”。用户在 ChatGPT 中同时上传已认可的多张效果参考图，模型以参考图维持造型、材质、线条、色彩层次与细节密度；文字 prompt 只补充汉字身份、兵器结构、占格比例、动作状态及纯白底等技术约束。下文原固定风格前缀与风格试验 prompt 仅保留为历史记录，不再作为当前出图入口；白底、命名、抠图、尺寸和 §5 验收标准仍然有效。
> ChatGPT 实际下载的方图可能是 1254×1254 等非 1024 尺寸；`_inbox` 应接受边长不低于 1024px 的方图，由入库工具统一归一化，不能把精确 1024px 当作拒收条件。

## 1. 历史风格基准（已由“效果参考图主导”取代）

**国潮厚描边扁平** —— 高饱和平涂 + 统一黑描边 + 单层硬边阴影。选它是因为：小尺寸可读性最好、AI 出图一致性最高、微信小游戏包体最省。

### 1.1 色板（严格限定）

| 用途 | 色值 | 说明 |
|---|---|---|
| 朱砂红 | `#D93A2B` | 我方主色 / 强调 |
| 藤黄 | `#F2B233` | 我方辅色 / 金币 / 高亮 |
| 竹青 | `#2E8B7A` | 中性 / 战场 |
| 靛蓝 | `#2B4C8C` | 敌方主色 |
| 玄紫 | `#5B3A8C` | 敌方辅色 / BOSS |
| 墨黑 | `#1A1A1E` | 描边 / 笔画 |
| 宣白 | `#F5EDDD` | 汉字填充 / 留白 |

**阵营辨识铁律**：我方 = 暖（朱砂 + 藤黄），敌方 = 冷（靛蓝 + 玄紫）。玩家必须在 64px 缩略下一眼分敌我。

### 1.2 形式规范

- 描边：**纯 `#1A1A1E`，均匀粗细，1024px 画布上 8px**（缩到 512 即 4px）；不许渐变描边、不许多重描边
- **主体最外圈必须是闭合的墨黑描边** —— 这是抠图管线成立的前提（见 §4.2）
- 上色：平涂色块；每个色块最多再加**一层暗部**（同色相压暗 15%，硬边，光源统一左上 45°）
- 禁止：渐变网格、写实光影、高光星芒、纹理噪点、笔触感、外发光、投影落到背景
- 视角：单位 = **正面微俯视 3/4，站立姿态**；战场 = 正交俯视
- 剪影优先：每个单位必须有独特剪影，纯黑剪影下也能互相区分

### 1.3 「汉字即兵器」的具体做法

单位主体 = **一个汉字**，笔画本身延展成兵器结构，两侧/下方挂少量机械或甲胄部件。
- 汉字必须**完整、正楷、笔画不缺**，占单位面积 55%~70%
- 汉字用宣白 `#F5EDDD` 填 + 墨黑描边
- 装饰部件不许压住汉字主笔画

**字形正确性的保底手段：参考图引导。**
纯文字 prompt 让模型写对汉字并不稳。标准做法是**同时喂一张该汉字的标准正楷图作为参考输入**（图生图 / reference image），可靠度远高于纯描述。首批就这么做，不要等出错了再补。

## 3. 历史 Prompt 模板（停用，仅供追溯）

**结构 = 固定风格前缀 + 主体段 + 硬性约束段。** 前缀和约束段每次原样复制，只改中间。
风格指令用英文（模型对风格 token 更敏感），汉字主体用中文并重复强调。

### 3.4 出图纪律
- **一次只出一张**，出完立刻对照 §5 自检，不合格当场重出，不要攒到最后
- 同批次（如 6 个我方单位）**在同一个对话线程里连续出**，让模型保持风格记忆；换线程必然漂移
- 出第 2 张开始追加：`保持与本对话中已生成资源完全一致的描边粗细、饱和度与明暗层次。`
- prompt 原文存 `Docs/Art/prompts/{文件名}.txt`，返工时才知道改了什么

## 4. 自动后处理管线（WO-A1）

### 4.1 抠图工具

本机有 **RTX 4070**，直接用 GPU 模型，不必将就轻量方案。

| 通道 | 方案 | 说明 |
|---|---|---|
| 主 | **rembg** + `birefnet-general`（或 `isnet-general-use`） | `pip install rembg[gpu,cli]`，onnxruntime-gpu 后端，边缘质量好 |
| 备 | **transparent-background**（InSPyReNet） | 主通道对某些资产不理想时切换 |
| 兜底 | 四角 flood-fill + 颜色距离阈值 | 平涂矢量 + 闭合黑描边的图，flood-fill 有时比神经网络更干净 |

**双通道跑取优**：AI matting 与 flood-fill 各出一份 alpha，脚本比对后择优（或取交集），差异超阈值时在质检报告里报警，交人工看。

### 4.2 背景色定为纯白 #FFFFFF

三种底色对比后的结论：

| 底色 | 问题 |
|---|---|
| 绿 `#00FF00` | 溢出补色是品红，极扎眼；**否决** |
| 黑 `#000000` | 与主体最外圈的墨黑描边 `#1A1A1E` 几乎同值，模型容易吃掉轮廓或留黑晕；**否决** |
| **白 `#FFFFFF`** ✅ | 与墨黑闭合描边对比度最大；白色溢出只是让边缘变浅，肉眼几乎不可见，且可 decontaminate 修净 |

**成立前提**：主体最外圈是**闭合的墨黑描边**（§1.2 已作为风格硬要求）。因此色板里的宣白 `#F5EDDD` 被黑描边与白底隔开，flood-fill 不会漏进主体内部，AI matting 也不会误判。

### 4.3 白色描边由程序生成，不让 AI 画

需要在深色战场上强化剪影时，**抠图完成后对 alpha 做膨胀并填白**，生成 6~8px 均匀白 rim。

放到后处理而不是让 AI 画，有三个好处：
1. AI 画的 rim 粗细必然不一致；程序生成的永远均匀
2. 要不要 rim 变成**一键开关**，不用重出图
3. 顺带解决深色地面上 64px 剪影发糊的问题——白捡一个可读性提升

### 4.4 处理链（`Tools/art_intake.py`）

```
1. 读 _inbox/*.png，按文件名解析 类别/id/状态
2. 双通道抠图：rembg(GPU) + 四角 flood-fill → 两份 alpha
3. 择优/取交集，差异超阈值则在报告里标记待人工确认
4. alpha 阈值化（平涂图用硬边更锐利，保留 1px 抗锯齿过渡）
5. decontaminate：半透明边缘像素用邻近不透明像素的颜色回填，消除白色渗色
6. [可选开关] 程序化白 rim：alpha 膨胀 6~8px 填 #FFFFFF
7. 按 alpha 包围盒自动裁剪
8. 等比缩放到规范尺寸，按类别锚点贴进画布
   单位 → 底部居中，底部保留 8% 空白
   UI/FX → 正中
9. 输出到 Assets/Art/{Units|UI|Battlefield}/...（无损 PNG）
10. 质检：半透明像素占比 / 主体占比 / 是否触边 / 双通道差异 / alpha 孔洞
11. contact sheet → Docs/Art/_review/{日期}.png（原尺寸行 + 64px 缩略行）
```

### 4.5 Unity 侧自动导入（`Editor/ArtPostprocessor.cs`）

按路径规则自动设置，**不需要任何人点 Inspector**：

| 路径 | Texture Type | PPU | Pivot | 其它 |
|---|---|---|---|---|
| `Art/Units/**` | Sprite (Single) | 100 | Bottom | 无 mipmap，Bilinear，Max 512（BOSS 1024） |
| `Art/UI/**` | Sprite (Single) | 100 | Center | 九宫格资产写 border，无 mipmap |

### 4.6 占位资源（保证代码轨永不阻塞）

`art_manifest.json` 里缺图的 id，由生成器自动产出「阵营色底 + 汉字 + 黑描边」的占位块。
**代码轨从第一天就能跑完整画面**，真图到位后直接覆盖，无需改任何代码。

## 5. 验收标准（验收方看 contact sheet 逐条对）

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 汉字正确 | 字形完整、无缺笔、无生造字、无镜像 |
| 2 | 64px 可读 | 缩略图能认出汉字与兵种类别 |
| 3 | 阵营可分 | 缩略图一眼分敌我（暖 vs 冷） |
| 4 | 风格一致 | 同批次描边粗细、饱和度、暗部逻辑一致 |
| 5 | 抠图干净 | 无白晕、无半透明脏边、无 alpha 孔洞、无缺角 |
| 6 | 构图合规 | 单主体、居中、留白达标、未触边 |
| 7 | 剪影独特 | 纯黑剪影下各单位能互相区分 |
| 8 | 无污染 | 无文字/水印/边框/多视角 |

任一项不过 → 打回重出，并把失败点写成显式负面约束加进 prompt。
第 1 项连续失败 → 强化参考图引导（换更标准的正楷字形图、提高参考权重）；仍不行则该字换一个同义汉字（如「弩」→「箭」）。
