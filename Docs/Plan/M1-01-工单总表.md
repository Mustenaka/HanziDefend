## WO-02 · JSON 数据编辑器

**目标**：JSON 是唯一真源，但真人调试测试需要可视化编辑，不该手改文本。

**实现建议**（可自行换更好的做法）：**JSON ⇄ 影子 ScriptableObject ⇄ 原生 Inspector**。
`JsonUtility.FromJsonOverwrite` 把 JSON 灌进临时 SO，白嫖 Unity 原生 Inspector（连 Undo 都免费），点保存再序列化回 JSON。影子 SO 不入库。

**交付物**
- EditorWindow `HanziDefend/Data Editor`：左侧列出 `Assets/GameData/*.json`，右侧编辑
- **表格视图**：所有兵种数值一屏批量编辑（IMGUI 表格），比逐个点 Inspector 高效得多
- schema 校验：字段缺失、枚举非法、数值越界即时标红
- 保存前 **diff 预览**；「重载」丢弃未保存修改；关窗有未保存提示
- 保存时保持稳定的字段顺序与缩进，保证 git diff 干净

**验收标准**
- 改一个数值 → 保存 → JSON 文件 diff 只有那一行
- 非法值被拦下且提示明确
- 关窗不丢数据
- `read_console` 无 Error

## WO-B1 · 战斗系统内核

**目标**：一个能被手动驱动、跑完整场战斗的 `BattleSystem`。

**交付物**
- `Gameplay/Battle/`：单位实体（队伍、等级、当前属性、位置、朝向、状态机 Idle/Move/Attack/Dead）
- `BattleSystem.Tick(float dt)`：**可被测试代码连续调用**的公开方法，内含移动、索敌、进入射程、攻速冷却、开火、伤害结算、死亡、掉金币
- 战斗场景初始化设 `Physics2D.simulationMode = SimulationMode2D.Script`，每 tick 手动 `Physics2D.Simulate(dt)`
- 索敌用 `Physics2D.OverlapCircleNonAlloc`，重定向节流（默认 0.2s）
- 同列不重叠的简单位置排斥
- 事件流 `IBattleEvents`（UnitSpawned / UnitAttacked / DamageDealt / UnitDied / CoinDropped）；表现层只订阅事件，不反查内部状态
- 测试：两单位对轰的伤害与死亡时刻、射程边界、攻速节奏、掉金币累计

**验收标准**
- `run_tests` 全绿，战斗相关用例 ≥ 15 个
- 测试里能构造「3 弓 vs 5 卒」，手动 Tick 到一方全灭并断言结果
- 同 seed 两次运行事件序列一致（确定性回归）

**边界**：不做波次、不做 BOSS、不做特殊索敌、不做任何表现。

**交付物**：结算弹窗（3 卡 + 重随 + 看广告）、阶段切换过场、大关通关/失败页。
**验收**：截图交审；交互无死锁（任何情况下都有出口按钮）。

## WO-E1 · 数值批跑与调优

**交付物**：`BalanceRunner`（PlayMode 测试或 Editor 菜单），手动 Tick 批量跑 N 局，输出 CSV：胜率、平均时长、各兵种 DPS 与存活时长、金币曲线。基于结果调 `GameData/*.json`。
**验收**：100 局 < 60 秒；调优后首关胜率 55%~75%，第 5 小关 30%~50%；单局时长 90~150 秒。

## WO-E2 · 手感与音频占位
命中停顿、震屏、出兵/合成/胜负音效调用点 + 占位音；音量总线。**验收**：无音频文件时不报错。
