# WO-C9 · 整卡渲染 + 等级可读 + 信息面板 —— **有条件通过**

## 视觉目标达成了（看图确认）

- **整卡渲染**：「重骑兵」是跨 3 格的**无缝**长卡、「肉盾」跨 2 格、
  「长矛」「弩兵」竖卡且**名字竖排** —— 名字方向随卡形，与参考图一致
- **等级一眼可分**：绿1 / 蓝2 / 紫3 / 金4，左下角数字角标 + 同色边框。
  卒1绿、弓2蓝、火3紫、冰4金、肉盾3紫、重骑兵2蓝、弩兵4金，清清楚楚
- **格子边界**：内嵌凹槽方案，空格读作凹槽，「这里是一格」终于看得出来
- **撤销的可发现性**：手牌区标题改成「手牌 · 拖回此处可撤回部署」，
  不用玩家猜有没有这个功能

## 六处工程判断值得点名

**1. 两层分离（棋盘层 + `unitLayer`）不是洁癖。**
它让新增的整卡渲染**完全避开拖拽帧**，于是 WO-C4 的 13 条计数门禁一条没动。
在一个刚因为「拖拽帧干太多活」被打回过的模块上，这个架构选择是有针对性的。

**2. `CreateSolid` 只在朝外的边收缩** —— 所以 3×1 是无缝长卡而不是三块拼接，
L 形缺角是真缺。**描边逐边画（没有邻居才画）**，因为包围盒边框会把缺口一起框进去。
这个细节不实际画一遍是想不到的。

**3. 角标钉在实际存在的左下 tile 上。**
`chc` 缺左下，钉包围盒会让角标悬在空缺口里。它想到了这个边界。

**4. 配色表用 `#RRGGBB` 字符串而非 `Color`**，因为 `Data/` 按架构必须保持纯 C#；
并加了**逐位十六进制校验**——防止拼错时 Unity 静默解析成品红。
「静默变品红」是个很具体的失败模式，能预判它说明想过真实出错场景。

**5. 撤销拒绝已合成单位的理由是对的。**
「退 1 张 = 销毁两次合成，退多张 = 凭空造卡，两条都在改合成经济」——
而工单边界写死了不改合成规则。**它没有硬做，而是识别出这是越界并记了债。**

**6. 落点判定排在 anchor 判定之前。**
手牌在网格下方，先判 anchor 会把拖回手势当成「拖出部署区」弹回，功能永远触发不了。
这是必须实际调试才会撞上的顺序问题。

## 负对照做得干净

塞回旧渲染 + 去掉撤回分支 → **红 20 条**；配色表、`CardEconomy` API、信息面板
**9 条正确保持绿**（探针没动那三层）。
**红的范围恰好等于探针触及的范围**——这叫归因干净，不是「一改就全红」的粗放验证。

## 必改项（一条，视觉）

### 单位美术图被等级色底盖住了

用户最初的抱怨是「拖拽前是图片，落位后生效的是纯文字」。
现在改成了「等级色底 + 大字 + **几乎不可见的美术图**」——比之前好，但**方向仍然反着**。

参考图 `Docs/Note/pic/7725099a014d0171abe327db371f6d7e.png` 里：
**美术是卡面主体**（「轻轰炸机」那张飞机图很清楚），汉字压在美术**之上**，
等级色只出现在**边框与角标**。我们现在是色底压住美术。

「链甲兵」那张手牌尤其明显：美术是噪点状的占位图，与文字叠在一起很脏。

**处理**：把层级关系倒过来——
美术图铺满卡面作为底，等级色只保留在**边框 + 角标 + 一层很淡的叠色**，
汉字加描边/阴影压在美术之上保证可读。
真美术接入后这条会更重要，占位图阶段就该把层级定对。

## 建议项

**1. 效果卡与单位卡视觉语言不统一。**
手牌里「攻城」是个纯紫小方块，无角标、无形状感，和旁边的单位卡完全两套语言。
效果卡不占格可以理解，但至少该有一致的边框与稀有度表达。

**2. 多格卡的字号偏小。**
「重骑兵」横跨 3 格，字反而比 1×1 的「卒」小。参考图里「轻轰炸机」是**撑满卡面**的。
字号应随卡面尺寸放大，而不是固定值。

**3. 手牌区仍偏左**，右侧留白。这条从 WO-C4 提到现在还没解决。

29 条用例全绿也拦不住「面板盖住手牌」这种问题。
