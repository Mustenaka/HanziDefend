## 加分项

**1. 定点文本替换而非整文件重序列化。**
`ReplaceToken` 用 Newtonsoft 的 `IJsonLineInfo` 拿到行号列号，只对目标值做文本拼接，其余字节原样保留。这是「diff 只有一行」唯一靠得住的做法——整文件重序列化必然会动到无关字段的换行与排序。

**2. `SaveWithoutChanges_IsByteIdentical`。**
这个用例挑得很准。它锁死的是「工具本身不 churn 文件」，比逐个断言字段值强得多——只要这条绿，就不可能出现"打开看一眼再关掉，git 里多了 200 行 diff"这种恶心情况。

**3. `RealGameData_PassesFullWorkspaceValidation`。**
校验器拿**真实出货数据**跑，而不是只跑构造的 fixture。这意味着以后任何一次数值改动如果破坏了跨文件引用，测试会直接红，而不是等到运行时才炸。

**4. 三类悬空引用都覆盖了**：`waves → unitId`、`commanders → effectId`、`effects.SpawnUnit → unitId`。这正是 JSON 多文件真源最容易腐烂的地方。
